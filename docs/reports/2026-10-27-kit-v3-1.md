### Limits, stated
1. **No guard checks when `guard.mjs` is missing.** A day session whose `guard.mjs` is missing or can't load runs with
   no guard checks at all, the git/gh option checks and the merge check included.
   - That is Mustafa's decision, and the same rule `guard.mjs` applies to a broken rules file (R3c).
   - "Merges fail closed" therefore holds while the guard loads. The comment at `routine-guard.mjs:601` ("for every
     session") is read the same way; C6 keeps that file unchanged in A1.
   - The server-side backstop already exists: main is protected, and merging needs a PR with `gate` and `smoke` green.
2. **A guard written to fail open.** A `guard.mjs` that exits 0 early, or removes the bootstrap's listener, still lets a
   routine through: a bootstrap can't defend against the code it is told to run. The controls there are that routines
   can't write `.claude/` (`protectedRel`), the working rule, and main's protection.
3. **A crash, hang or invalid output after loading.** A `guard.mjs` that loads and then crashes, hangs or prints invalid
   JSON still blocks the call. That costs availability, not safety. A hang holds a day session for up to the default
   600-second hook timeout per call; a shorter `timeout` is a separate decision. The real `guard.mjs` does none of these
   as written.
   - In such a broken state a PermissionRequest deny loses its `interrupt`, and the reason reads "ended without a
     decision". It still blocks.
4. **A large input** (L2, deferred). With `guard.mjs` missing, the bootstrap exits without reading its input. Inputs over
   about 60 KB give the host a broken pipe (EPIPE), whose handling is host behaviour. Either way a routine is never let
   through, and the settings reload (a small input) is unaffected.
5. **The stderr reason on other platforms** (not verified). On macOS or Windows pipes the reason written just before
   `exit(1)` may not arrive. The exit code is what blocks.
6. **`node` failing to start.** One day-session freeze remains: `node` itself failing to start. The project requires
   Node 22.13+.
7. **This PR's old commits.** Its commits up to 5be7d37 still carry the unfixed hook. The working rule covers them: a
   session never switches its main folder, and other branches and old commits go in a separate folder (git worktree).
8. **Q3, a follow-up:** `routine-guard.test.mjs` fails 9 of 192 on Windows.
   - This is pre-existing: the credential checks match forward-slash paths only.
   - CI runs only the gate and smoke, not the hook tests.
   - The follow-up: the hook tests in CI (a Linux job first), separator-agnostic path handling in `routine-guard.mjs`,
     then a Windows job.
