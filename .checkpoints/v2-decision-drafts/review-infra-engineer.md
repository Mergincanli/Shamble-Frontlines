The trade-offs I was asked to judge hold up:
- Pages with Workers static assets as the alternative.
- One small staging VM rather than one VM per pull request.
- Dedicated vCPUs, with shared vCPUs measured before they are trusted.
- A fixed fleet first.
- `tracing` and Prometheus, with no distributed tracing.
- A recorder inside the room, with no live balance dashboard.

Nothing in my domain is a generic "for later" feature. Parquet compaction, Grafana Cloud, K2 automation and OTLP are
each held back until a need shows. The 48-player figures hold:
- egress is about 9.2 TB a month per VM at 4 rooms, about 18.4 TB at 8, both inside the 20 TB included;
- 8 rooms × 64 MB fit both VM sizes.

Nothing decides the look.

## Questions for Mustafa or the Advisor

1. **UNRELEASED-ART (Mustafa):** Must unreleased art stay unseen, or is a preview behind a login enough?
   - *Why it matters:* the repository is public, so every model file committed to it can be read by anyone, whatever the
     preview wall does (finding 12).
   - *Options:*
     - (a) a login on previews is enough: models are committed as now, and the wall covers previews only;
     - (b) models live outside this repository, in a private store: the build fetches them with a secret, so the build
       job is no longer secret-free (the store is not researched);
     - (c) the repository becomes private: CI then draws on paid minutes, on 2-CPU runners (prices not read).
   - *Recommendation:* (a) until the first unreleased model needs hiding. Decide it together with ASSET-RESEARCH, before
     the first authored model.
2. **ROOMS-COUNT-RULE (the Advisor, with test-engineer):** Is the rooms-per-VM figure for the budget the most rooms that
   keep every room inside the server tick budget (R2-ROOM-REC2 mark 1), or also within 10 % of a room running alone
   (mark 2)?
   - *Why it matters:* mark 2 checks isolation. Used as a capacity limit, it can fail a room far inside its 16.67 ms (a
     3.0 ms room at 3.4 ms is 13 % worse), which halves the density and doubles the goal fleet (0006:881).
   - *Options:*
     - (a) both marks, as A-2 and the draft read it (r6:516–522);
     - (b) mark 1 for the count, with mark 2's share reported beside it.
   - *Recommendation:* (b) for the budget figure; (a) stays the fairness check on the chosen density.
3. **SPIKE-VM-ACCESS (Mustafa):** How do sessions get VMs for the spikes and the phase-1 tick bench?
   - *Why it matters:* a Hetzner API token can create and delete every VM in its project, and sessions may not read
     secrets (CLAUDE.md). Yet the bill mark needs VMs deleted after every session (finding 14).
   - *Options:*
     - (a) Mustafa creates and deletes every VM by hand;
     - (b) a separate Hetzner project for spikes and benches, with its own token, set by Mustafa where a session can use
       it without reading it;
     - (c) a self-hosted runner (ruled out for now, B11).
   - *Recommendation:* (b), never the production project's token.
4. **RELEASE-WINDOW (Mustafa):** At the start, are releases done in a window, or kept live?
   - *Why it matters:* without a rule, every deploy refuses players whose client and server versions differ (finding 1).
   - *Options:*
     - (a) a short release window: rooms drained, then client and servers switched together (simplest);
     - (b) live releases: both server versions run side by side and the lobby routes by protocol version (more to build).
   - *Recommendation:* (a) while playtests are scheduled; (b) when players arrive unscheduled.
5. **DOMAIN (Mustafa, after the Advisor's OQ-0006-5 read):** Do you register a domain for the game servers and the
   lobby, and when?
   - *Why it matters:* production certificates, the lobby's HTTPS and the guest cookie all need one, and so does a
     trusted `wss` certificate in the netcode proof test, unless a private test certificate authority is used
     (finding 6).
   - *Options:*
     - (a) a private test certificate authority for the proof test, and a domain before slice 3;
     - (b) a domain before the proof test.
   - *Recommendation:* (a).
