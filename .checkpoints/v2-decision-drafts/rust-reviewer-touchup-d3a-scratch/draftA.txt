float `%` operator are not on the list. std's `f32` and `f64` pages state that both return "the rounded
infinite-precision result" (std 1.99.1's, read by the verifier on 2026-11-02; rustc 1.97.0's std says the same), yet
rustc 1.97.0's `div_euclid` returns 3 for (3 + 2^-22) ÷ (1 + 2^-23), whose exact Euclidean quotient is 2, in `f32`
and `f64`, and is one off on its sign mirrors too (the verifier's fixcheck-d3a and skeptic-6 runs, 2026-11-03).
Determinism needs the same bits on every target, and an error every target shares passes that check; correct rounding
is a separate claim. So they may join only once PM-0004-22, extended to them, shows that fixed inputs, that case and
its mirrors among them, give the same bits on every target and equal an exact Euclidean reference; no source read
states the float `%`'s precision (the Rust Reference defines it only by truncating division and the dividend's sign),
and review, not the lint, catches the operator. Transcendental maths only
