303: 1.38.0 · Sourcepub fn div_euclid(self, rhs: f64) -> f64
304: Calculates Euclidean division, the matching method for rem_euclid.
305: This computes the integer n such that
306: self = n * rhs + self.rem_euclid(rhs).
307: In other words, the result is self / rhs rounded to the integer n
308: such that self >= n * rhs.
309: §Precision
310: The result of this operation is guaranteed to be the rounded
311: infinite-precision result.
312: §Examples
313: let a: f64 = 7.0;
314: let b = 4.0;
315: assert_eq!(a.div_euclid(b), 1.0); // 7.0 > 4.0 * 1.0
316: assert_eq!((-a).div_euclid(b), -2.0); // -7.0 >= 4.0 * -2.0
317: assert_eq!(a.div_euclid(-b), -1.0); // 7.0 >= -4.0 * -1.0
318: assert_eq!((-a).div_euclid(-b), 2.0); // -7.0 >= -4.0 * 2.0
319: 1.38.0 · Sourcepub fn rem_euclid(self, rhs: f64) -> f64
320: Calculates the least nonnegative remainder of self when divided by
321: rhs.
322: In particular, the return value r satisfies 0.0 <= r < rhs.abs() in
323: most cases. However, due to a floating point round-off error it can
324: result in r == rhs.abs(), violating the mathematical definition, if
325: self is much smaller than rhs.abs() in magnitude and self < 0.0.
326: This result is not an element of the function’s codomain, but it is the
327: closest floating point number in the real numbers and thus fulfills the
328: property self == self.div_euclid(rhs) * rhs + self.rem_euclid(rhs)
329: approximately.
330: §Precision
331: The result of this operation is guaranteed to be the rounded
332: infinite-precision result.
333: §Examples
334: let a: f64 = 7.0;
335: let b = 4.0;
336: assert_eq!(a.rem_euclid(b), 3.0);
337: assert_eq!((-a).rem_euclid(b), 1.0);
338: assert_eq!(a.rem_euclid(-b), 3.0);
339: assert_eq!((-a).rem_euclid(-b), 1.0);
