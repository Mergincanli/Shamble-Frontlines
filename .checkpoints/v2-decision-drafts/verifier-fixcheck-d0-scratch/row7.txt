| 7 | IPv6: an interface id is 64 bits, so a /64 is one subnet with 2^64 addresses, and per-address limits key on IPv6 /64 | ADR 0001 lines 421–424 (part 10), also lines 641, 743, 1563 (the /64 key); ADR 0006 lines 401–403 (part 10), line 1451 (sources) (SA-7) | confirmed, with a note | RFC 4291 (www.rfc-editor.org, 200, fetched 20:34) §2.5.1 "Interface Identifiers", page 8: "For all unicast addresses, except those that start with the binary value 000, Interface IDs are required to be 64 bits long and to be constructed in Modified EUI-64 format." §2.5.4 "Global Unicast Addresses", page 10: "All Global Unicast addresses other than those that start with binary 000 have a 64-bit interface ID field (i.e., n + m = 64)", so the subnet prefix is 64 bits and one subnet holds 2^64 addresses, as the drafts say. Note: the drafts do not say a /64 is what an end site gets, and they should not: RFC 6177 (BCP 157; 200, fetched 20:37) §2, pages 5–6: "this document still recommends giving home sites significantly more than a single /64, but does not recommend that every home site be given a /48 either" (/56 is its example). So one home client may hold 256 or more /64s; a per-/64 cap is per subnet, not per customer. The drafts already keep the prefix length as data, which covers this. | none required; optional, ADR 0001 line 422–423 after "2^64 addresses": "and an ISP usually gives a home more than one /64 (RFC 6177 §2), so the prefix length may need to be shorter" |
