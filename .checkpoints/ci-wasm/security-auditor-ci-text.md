## B9. Threat model, answers and findings (DONE)
**Threat model for this job** (durable): who can act: (1) a hostile dependency (crate build script or proc macro, npm package): runs only inside the cut; (2) a pull request's author: the run uses the pull request's merge commit (S6), so the author can change this workflow in that run; GitHub's rules bound it (fork: read-only token, no secrets, first-time contributors may need approval: S6, S10), not our text; (3) an attacker on the tool's route (network, CDN, a swapped asset): stopped by his size and sha256 before anything else, and GitHub's check anchors the origin; (4) GitHub and its runner image: trusted platform (it runs both the check and the CI). What there is to take: the job's token (contents: read on a public repository; read-only in fork pull requests; ends with the job, at most 6 hours: S5), CI's verdict, and his tool rule. No secret, cache, artifact or deploy.

**Q1 the token.** Reach: an installation token limited to this repository (S5), contents: read plus metadata, everything else none (S11); in a fork pull request read-only whatever the text says (S6). Later steps: a step's env is that step's (S11), and the step writes no environment file, so no later step's environment holds it; the cut: `env -i` drops it, and its processes (uid runner, gid nogroup, no groups) cannot read the memory or environ of the runner's own processes (the kernel's ptrace check wants the same gid: reasoning, not seen on a runner). But the token is in the job anyway: checkout's token input defaults to it, the runner holds it, and any step with sudo can read the runner's memory; the cut reaches it after the cut through checkout's post step (CI-CUT, known). So the new env line adds exposure only to gh and its children in that one step. Floor: 2.93.0 is right (B8a); the test fails closed on an empty version, open on a non-numeric one (F-FLOOR, Low). GH_HOST, GH_REPO, GH_ENTERPRISE_TOKEN, GH_CONFIG_DIR: only the workflow text or an earlier step's environment file could set them; before this step only the SHA-pinned actions and the workflow's own lines run; the enterprise token is the one the CVE sent to non-GitHub hosts and nothing sets it here; `--repo` fixes the repository: no pin needed. gh reads no repository-local config (its config is GH_CONFIG_DIR, default ~/.config/gh: S2), needs no git remote with --repo, cannot be shadowed by an extension or alias for a core command; nothing a pull request plants in the tree is read; and a pull request could rewrite the workflow anyway. Optional: `GH_TELEMETRY: "false"` on the step (S3: gh may send a usage event; no token or argument values listed).

**Q2 the route.** Order holds: values (text) -> download -> size -> sha256 -> GitHub's check -> members -> one member -> root-owned install -> size and sha256 of the installed file -> build.mjs's check before each run. Between the archive check and the extraction nothing else runs, and the installed program is checked again by its own sha256, so a change of the archive in between could not pass. Between the install and the cut: `cargo fetch --locked` and `npm ci --ignore-scripts` run no package code and no sudo; they cannot write root-owned /opt/wasm-bindgen-0.2.130. Inside the cut: no_new_privs (no sudo), uid runner with no groups: the 0555 file and its folder (install -D makes it 755 whatever the umask: T7) cannot be changed; a rename of the folder needs write on /opt, which the text neither prints nor checks (F-OPT, Low). Shell lines: quoting is sound; `grep -qxF --` exact lines (a swap of the two bytes values passes the loop and fails closed in build.mjs: T6); awk refuses link, hard link, space, fifo, > 64 MiB (T4); the named member with --strip-components=1 gives only the program (T5); `ls -A` compare plus [ -f ] && [ ! -L ] (T5, T8); sed cuts the query at the first `?` (BRE, T2); a failing curl stops the step with its own code under -eo pipefail (T3). WB_*: public values, visible to every step of the job and the actions, kept out of the cut by env -i, not matched by build.mjs's refused pattern (WASM_BINDGEN_.*): no collision. **The one real defect is F-QUOTE (line 172).**

**Q3 network and the cut.** Before the cut the text adds no repository or package code: grep reads the module as text; the rest are the image's programs on the archive pinned by his sha256. The tool's first run is inside the cut, after GitHub's check (his CI-WASM (a)). Inside the cut, new: his wasm-bindgen program, Vite's build, vitest on the Wasm, Playwright with serve.mjs and Vite's servers, the image's Chrome. Each reaches loopback in the namespace only, and the files the runner's uid owns (the workspace, $HOME with the runner's _work folder). `--no-sandbox` (Playwright 1.65.0 default: coreBundle.js:45187) does not matter here: the sandbox guards against hostile web content, and the content is the repository's own page (in a pull request its author's code, who controls the whole run); a renderer exploit would gain only what every build script inside the cut already has. Left for another run: nothing (no cache, no artifact, a fresh machine). Left for a later step of this job: yes, not "none": checkout's post step runs after the cut with the network and sudo (S7), and the cut's processes can rewrite its code or write the step's environment files (S8): CI-CUT, Medium, known, part 2 on the gate v2 list. The text adds no `uses:` step (no wider route) but more package code that could use it; what it could take there is the read-only token of a public repository.

**Q4 CHROME-SOURCE.** Security side: (a). Residual risk, one line: its version and bytes change whenever GitHub updates the image, pinned and reviewed by no one here (GitHub installs Google's package over HTTPS when it builds the image: infra S3.8), and it only ever sees 127.0.0.1. **Q5 PERM-ATT and P-GH.** PERM-ATT: (a). `attestations: read` would only let the token read this repository's attestations (none; public anyway), so (b) is harmless too, but nothing shows it is needed, and a missing permission fails closed at GitHub's check, before the tool runs.
