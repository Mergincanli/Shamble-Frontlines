### N4 (Low, record for cs3, when the generator enters) the seed is a mandatory World field, written right after the tick

### N5 (Low, a naming trap for cs3) the page's post number is not the command's sequence
boot.ts:116-119 (u32 per drawn frame, >>> 0), messages.ts:18, sim-wasm lib.rs:123-132 (input(sequence), newest_input). protocol/messages.rs:56 ("their sequence numbers consecutive"), :78 (Command.sequence: u16, wraps), ADR 0001 part 5 :233-234. Posts come per frame (60-144 Hz), a catch-up wake applies one post to up to 7 ticks and a hidden or stalled page posts none, so copying the post number into the command breaks "consecutive" and "forward only". Fix: call it the post number (messages, Wasm parameter, report); the command's sequence is the endpoint's own, one per command. >>> 0 itself is right (it wraps exactly where Rust's u32 does and isCount accepts the whole range).

### N6 (Low, extension for cs3) the world always starts at tick 0
world.rs:24-26. ADR 0001 Test plan :1823-1827 (the L1 wrap test starts the server tick a few ticks below a multiple of 65,536) and :1531 (S30 starts 1,800 ticks below 65,536). Fix in cs3: the start tick as a match-setup value of World::new (the authority's), not a test back door; LocalSchedule is unaffected.

### N7 (Low) a non-finite due time stops the match silently
pacing.ts:92-106, :119-125 (and host.ts:134 with or without Math.ceil): NaN or Infinity from step/rebase makes nextDue <= now false for ever; Math.max(0, NaN) is NaN, Math.ceil(NaN) NaN, and setTimeout converts NaN or Infinity to 0 (WebIDL long), so the Worker loops on empty wakes: no tick, no drop, no error. Unreachable in local play (performance.now() is finite; rust-reviewer showed now = NaN gives NaN); online the server-time estimate is the new source. Fix: throw on a non-finite due time in the Pacer (constructor, wake, resume) so the host's error path reports it; one unit test.
