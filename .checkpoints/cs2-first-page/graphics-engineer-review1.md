### Source: SwiftShader src/Device/Renderer.cpp, DrawCall::setupLine (raw.githubusercontent.com/google/swiftshader/master, read 2026-11-19 via summary with short quotes)
- rejects only when both ends are behind the eye: `if(P0.w <= 0 && P1.w <= 0)`; computes the screen direction BEFORE clipping from perspective-divided ends: `dx = W * (P1.x / P1.w - P0.x / P0.w)`; builds the line's quad/parallelogram from that direction (Bresenham default path picks it by the octant of dx, dy), then Clipper::Clip with CLIP_FRUSTUM (near plane included when depthClipEnable).
- => with ONE end behind the eye (w < 0) the divided position is mirrored, the direction/octant is wrong, and the line vanishes or draws wrongly. Not near-plane clipping as such: a line with both ends in front of the eye (0 < w < near at one end) should clip correctly. Hardware clips lines in homogeneous space before the divide, so Brave draws them. Confidence moderate-high (source read, not run). Discriminating check: one line ending between eye and near plane (drawn) vs one ending behind the eye (missing).
