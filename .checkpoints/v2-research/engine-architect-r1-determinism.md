S1. https://webassembly.github.io/spec/core/exec/numerics.html (WebAssembly 3.0 core spec, page dated 2026-10-23; read 2026-10-27; official). Sections "Floating-Point Operations" / "NaN Propagation" and "Relaxed Operations".
  - FP follows IEEE 754 with qualifications; all operators round-to-nearest ties-to-even; no directed rounding; FP exceptions not observable (non-stop mode). [confirmed]
  - NaN propagation: for ops other than fneg/fabs/fcopysign returning NaN, the sign is non-deterministic; if all input NaN payloads canonical, output payload canonical, else picked non-deterministically among arithmetic NaNs. "In the deterministic profile, only positive canonical NaN outputs are produced." [confirmed]
  - fma_N (IEEE fusedMultiplyAdd) is defined only as the fused alternative of relaxed_madd; no scalar fma instruction is mentioned as using it. [confirmed per fetch summary: "fma_N appears only in the definition of frelaxed_madd"]
  - Relaxed ops: each has a global parameter choosing among allowed results; "may depend on ... hardware"; "parameters are constant during the execution of any given program". relaxed_madd: fused or unfused (implementation-dependent rounding); relaxed_min/max differ for NaN and opposite-signed zeros; relaxed_trunc non-deterministic for NaN/out of range; relaxed_swizzle, q15mulr, dot, laneselect likewise. Deterministic profile: every parameter = 0 (unfused madd, regular min/max, saturating trunc...). [confirmed]
  - Subnormals: not mentioned as flushable in this page (only in relaxed_trunc definition). No flush-to-zero allowance seen. [confirmed absence in the page as summarised; medium]

  - const evaluation may choose different NaN bit patterns than runtime. [confirmed]
