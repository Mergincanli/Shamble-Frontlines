## 1. What Shamble VFX is today
**Packages** (npm workspaces, Node 22.x: root package.json:7-15):
- `packages/vfx-format`: the effect format's types, palette, defaults, words and export manifest types. Its main entry (src, 1,054 lines) "has no dependencies, so the game's runtime can import it" (src/index.ts:1-4); the zod 4.6.7 schema, checker and upgrades sit in `./validate` (1,040 lines; vfx-format/package.json:14-16); schema/effect.v5.schema.json (4,015 lines).
- `packages/vfx-runtime` (v0.1.0), the part made to ship in the game: src 3,197 lines of TypeScript (core 2,670 in 15 files; three/ 376: VfxRenderer 254, tsl 86, atlas 36; load 137; index 14) plus data/letters.json (1,397 lines). It exports TypeScript source, not built JS ("." -> ./src/index.ts, "./core", vfx-runtime/package.json:9-12).
- `packages/vfx-editor`: the editor (src and server 9,077 lines), with the export writer server/export.ts (311 lines, Node, run through Vite's ssrLoadModule) and the atlas packer src/atlas/pack.ts (155 lines). CLI: tools/export.mjs (70 lines).
- `packages/vfx-testpage` (src/main.ts, 342 lines): "plays effects by game event name, the way the game will" (:1-11), from the runtime and three.js only. tools/browser-check.mjs (1,303 lines) checks it.

**The runtime's API** (export.md:122-155; src/index.ts:5-14):
- Load: `const fx = await loadExport('/vfx/')` (load.ts:34-44; options: an injectable `fetch` and `decodeImage`) returns `{manifest, palette, atlas, effects, events, effectFor(event), lookup(id)}` (load.ts:125-136); failures throw `VfxLoadError` (export.md:147-155). The loader does plain checks only; the full checker "stays in the game's build" (load.ts:1-4, 68-123).
- Create: `const vfx = new VfxRenderer(fx.palette, {renderOrder})`; `vfx.setAtlas(fx.atlas)`; `vfx.tier = 'low' | 'medium' | 'high'` (default high, VfxRenderer.ts:79-80); `scene.add(vfx.object)`.
- Play by event name: `player.start(fx.effectFor('rifle.shot')!.id, { seed, nowMs, faction, relation, viewerDistanceM, inputs: { origin, target } })` on an `EffectPlayer`, in world metres, y up (export.md:122-142).
- Each frame: `vfx.begin(camera); vfx.drawPlaying(player, nowMs, fx.lookup); vfx.end();`, then the game renders. `vfx.stats`: triangles, draw calls, items, effects, `notDrawn` (export.md:144-145).
- Teardown: `vfx.dispose()` frees the geometries, materials and texture (VfxRenderer.ts:224-230) but does not detach `vfx.object`; `player.clear()` (player.ts:52-54).
- The model: effect + seed + time + inputs gives that moment's picture; it "keeps no hidden state" (README:103).

**The export folder** (export.md:5-13, 98-118): manifest.json (format "shamble-vfx-export", version 1, effectVersion 5, atlas size, `effects[{id, name, version, file, events}]`, `events{name -> id}`, "One event plays one effect"), palette.json (roles per faction, gradients), atlas.png with atlas.json (incl. the runtime's own "__white" and "__dot" blocks, vfx-format/src/export.ts:47), effects/<id>.vfx.json (format v5), editor.json ("the game ignores it"). Event names are lowercase dotted words (vfx-format/src/export.ts:12-17). The manifest holds no hashes. Exports are git-ignored (.gitignore:32-33, art stays out of the public repo): the clone holds no export, only two example projects (16 effects with proposed event names and placeholder images, tools/make-placeholder-images.mjs:1-3).

**What it depends on:** three.js only, through `three/webgpu` and `three/tsl` (VfxRenderer.ts:9-26, tsl.ts:18-20), as the peer `three "^0.187.0"` (vfx-runtime/package.json:16-18; its own pin 0.187.0); plus value imports from its sibling vfx-format's main entry (evaluate.ts:6, timeline.ts:5, words.ts:7, load.ts:10), declared `"@shamble/vfx-format": "*"` (vfx-runtime/package.json:13-15). So "imports only three.js" (README:99, CLAUDE.md:10) holds for third-party code; zod never enters (validate/index.ts:2-3).
**How it draws:** one Group of 4 Meshes, one per blend group (ground-multiply, ground-screen, ground, top; VfxRenderer.ts:93-112), each a `MeshBasicNodeMaterial` with a TSL `vertexNode` and `colorNode`, transparent, no depth write (tsl.ts:35-54); premultiplied CustomBlending, normal and additive in one draw (tsl.ts:12-14, 56-64); one shared atlas texture (VfxRenderer.ts:118-135). Every triangle is built on the CPU each frame and uploaded with update ranges (VfxRenderer.ts:189-218); "No compute" (:3). No sprites, instancing, post-processing or `ShaderMaterial` (grep of the runtime).
**Tests** (not run here): 536 unit tests (README:115) in 6, 11 and 17 files (format, runtime, editor); a headless browser check of 181 checks on WebGPU and WebGL 2 (README:152), drawn in software (README:174-175).
**Sizes:** no bundle size is written down; browser-check.mjs:40 prints the runtime's minified size at run time.
**Licence:** every package.json says `"license": "UNLICENSED"` and `"private": true` (root :3, 5; each package :4, 6); no LICENSE file.
**Finished and not:** "milestone 3" (README:7-9). "Not yet: sound, camera shake and hit-stop; a shade input ...; a way for tiers to drop parts of one layer" (README:274-281). Event names are "Milestone 3 proposals" (README:309-311; export.md:117-118). "No budget is decided yet" (cost.md:3-5). "Brave on Windows is not tested yet" (README:25-26). An open question must be answered before "Part B freezes the runtime" (README:376-378).

## 2. Against the game's drafts (one line each, with the draft's line)
- **Both backends, same result** (ADR 0003:125-131, F-A): yes by design: "TSL builds both WGSL (WebGPU) and GLSL (WebGL 2)" (tsl.ts:2-3), on `WebGPURenderer` with `forceWebGL` for the fallback (vfx-editor/src/preview/Preview.ts:109-110). Its own check passes when under 0.15 % of 2x2-averaged samples differ by more than 48 levels (browser-check.mjs:180-231, 1217-1230), and palette hexes match within 1 level (:1199-1202): a tolerance, not identity, and only headless in software.
- **Warm-up** (ADR 0003:146-149, "The match itself creates no new shader programs"; PM-0003-7, ADR 0003:1181): the runtime compiles nothing itself. Its 4 materials exist from the constructor (VfxRenderer.ts:100-101), but each mesh starts invisible (:107) and shows only when its group has triangles (:216). [inferred] Each blend group's pipeline compiles at its first draw unless the game's `compileAsync` warm-up makes the 4 meshes visible. The count stays 4 whatever the number of effects (no material per effect).
- **Allocation per frame** (ADR 0003:464, "Nothing in this flow allocates per frame"; PM-0003-29, ADR 0003:1204; plan.md:349 meets it at change-set 11): GPU-side buffers are reused (sink.ts:5; they double and never shrink, :101-108; a growth rebuilds the geometry, VfxRenderer.ts:194-198). The CPU path allocates every frame: `begin()` arrays and tuples (VfxRenderer.ts:147-155), a context object per effect (:161-175), `evaluate()`'s Maps, arrays and closure (evaluate.ts:130-139; timeline.ts:98-151), math helpers that return new tuples (math.ts:6-35, 50-62), `EffectPlayer.alive()` filtering each frame (player.ts:42-50), the `stats` getter (VfxRenderer.ts:220-222). Nothing in the repo measures allocation.
- **Pools and caps** (ADR 0003:270-272, "pooled per kind, with caps as tier data"): none in the runtime: no cap on playing effects, no throttle per event, a new object per start (player.ts:32-38).
- **What part 1 rules out** (ADR 0003:125-126; ADR 0002:427-432 for `eval`): nothing found. No `ShaderMaterial`, `onBeforeCompile`, `EffectComposer`, `RawShaderMaterial`, `WebGLRenderer`, `eval` or `new Function` in the runtime's source.
- **Randomness** (ADR 0004:328-330, the page's own generator): a stateless hash of the seed and layer ids (random.ts:1-27, 36-42); the caller passes the seed (player.ts:34); no `Math.random`. [inferred] It fits: the page's generator supplies the seed.
- **Time:** no clock of its own; it takes the caller's `nowMs` (VfxRenderer.ts:158-187; player.ts:22-23, 35); no `performance.now`, `Date.now` or `requestAnimationFrame` in its source. [inferred] The page can pass presentation time, which hit-stop needs (ADR 0003:459).
- **Draw calls:** at most 4 for all effects together (cost.md:18; sink.ts:136-141), under the 5 that ADR 0003:360-362 assumes for effects in the Low draw count. Triangles and screen area grow with what plays ("fires and glows reach the thousands" of sprites, cost.md:19), bounded only by the tier.
- **Which budget row:** its main cost is CPU, the time to build one frame's triangles (cost.md:22). That falls in the main-thread row (ADR 0003:343, at most 16 / 8 ms p99), which has no effects sub-row. The effects row (ADR 0003:350; PM-0003-21, ADR 0003:1196) is GPU time. cost.md:89-90 quotes that row's 2 / 1 ms beside its CPU figure. [inferred] Two numbers to gate, not one.
- **Quality tiers** (ADR 0003:388-391: the tier table holds the effect caps): Low, Medium and High per layer, one tier for all effects, timing unchanged (format.md:51-53; evaluate.ts:186-191). No counts or caps per tier.
- **Also for the picture:** colour follows `ColorManagement.enabled` (VfxRenderer.ts:148). Blending in linear light differs from the board's sRGB by about 18/255 at half-transparent edges; "The game's renderer setup decides" (README:302-304). Line widths in px at 1080p become metres through `pxPerMetre` 100.7 (evaluate.ts:64-65, 145), which `VfxRenderer.draw` does not pass (VfxRenderer.ts:161-175). [inferred] A game camera at another scale draws other ink widths than the editor.
- **Presentation decides nothing** (ADR 0005:1549-1558): the runtime takes inputs and returns only drawing and stats. [inferred] Nothing flows back to the sim.

## 3. How the runtime's code could reach the game's repository
What any route starts from: the runtime is `private` and `UNLICENSED` (§1); it exports TypeScript source; it needs its sibling vfx-format (`"*"`); its peer `three "^0.187.0"` means 0.187.x only (semver on a 0.x version), so the game's exact pin (ADR 0003:140-142: "the newest when the look proof test starts", r186 when researched) must be r187, and each one-step upgrade (ADR 0003:141) moves the runtime's peer too. Its bundle holds no editor code or zod (browser-check.mjs:33-39), which fits "`client` never reaches `editor`" (ADR 0002:207-209). The game's rules: one root `package-lock.json`, exact versions (ADR 0002:161-163); CI runs `npm ci --ignore-scripts` with the npm cache keyed on that lockfile (ADR 0002:602-603).
- **a. A published npm package at an exact version.** Needs upstream: drop `private`, choose a licence, build JS (its `vite build` exists, three left external, vfx-runtime/vite.config.ts:3-12) and publish the runtime with vfx-format's main entry (two packages, or one bundle), under a scope someone owns (unknown). Lockfile: one registry entry with an integrity hash; offline CI: cached like any package. Review: the game sees a version bump, not the code [inferred]. Against: a release upstream for every fix; publishing is Mustafa's call, not this repo's.
- **b. A copy in a package of the game's workspace (vendored, with its commit).** Needs: a package holding the runtime and vfx-format's main entry (about 4,250 lines of source plus letters.json), a note naming the commit, a script that re-copies and diffs. Lockfile: a workspace link only, three is the game's own pin; offline CI: nothing to fetch. Review: every line is seen in the change-set that brings it, under the game's strict tsconfig and lint (ADR 0002:416-432; [inferred] it may need edits to pass). Against: two copies drift, and an edit made only in the game's copy breaks the "same code" promise (README:5) [inferred]: fixes land upstream first, then are copied.
- **c. A git dependency.** The rules ban git dependencies for Rust only ("a git or other-registry dependency fails G5", ADR 0002:210-212); no npm rule was found. [inferred, from general npm behaviour, not checked: no web] npm installs a repository's root package, here the private workspace root, and has no selector for `packages/vfx-runtime`, so this route needs an upstream change (a repository or branch holding only the runtime). Lockfile: the commit; offline CI: `npm ci` fetches from GitHub unless cached. Review: a SHA, not the code.
- **d. A git submodule.** Needs: the repository mounted at a pinned commit, its two packages added to the game's workspaces, and a CI checkout that fetches submodules. Lockfile: workspace links, but [inferred] the mounted packages' dependencies join the game's lockfile (zod 4.6.7 from vfx-format; vite 8.3.8 and three 0.187.0 as dev pins). Offline CI: the checkout fetches the submodule. Review: a SHA per bump, the code unseen in the diff, and the whole repository (editor, tools) comes along. No rule in ADR 0002 names submodules (grep).

## 4. What must be proven before change-set 11 rests on it (checks that pass or fail)
- **C1. The same picture in the game as in the editor.** One effect at a fixed event, seed and time, drawn by the game's page and by the test page's `renderAt(event, timeMs, {seed})` (vfx-testpage/src/main.ts:207-227), same camera, 1920 x 1080, pixel ratio 1, same backend, over a fixed flat background, read back and compared; passes when the pixel difference is under a bar written into the plan before the run (upstream's backend bar, under 0.15 % of samples off by more than 48 levels, browser-check.mjs:180-231, is a candidate and is looser than identity), at three moments per effect (proposed). To set equal first: the camera's scale (`pxPerMetre` 100.7, §2), colour management and blending space (README:302-304), and the post chain: the test page renders with none (main.ts:144-153), while the game's ink, AO and glow read the shared scene pass (ADR 0003:117-119); [inferred] compare with the chain off, then on; which is wanted is OQ-0003-7's (plan.md:622). Smallest build: change-set 11's page with a debug flag that plays one event at a fixed seed and time, plus a readback. Mustafa's eye in Brave stays the gate (Brave is untested upstream, README:25-26).
- **C2. Its cost inside the budget on the weakest machine.** GPU: the effects alone within 2 ms p99 at Low (1 ms at High) (ADR 0003:350), reported per PM-0003-9 at change-set 11 (plan.md:527) and gated by PM-0003-21 at Slice 6 (plan.md:542); timestamp queries, Chrome on WebGPU and with `forceWebGL`, on the named minimum laptop (still unnamed: OQ-0003-1), never headless. CPU: `begin` + `drawPlaying` + `end` p99 as its own line inside the main-thread row (ADR 0003:343; proposed, no such sub-row exists). Load: the slice's heaviest scripted moment at Low (its make-up is a plan choice). Smallest build: change-set 11's page with that script and the measurement build's timers.
- **C3. No compile after the loading screen.** PM-0003-7's two counters (programs and the pipeline spy, ADR 0003:1181) equal after the warm-up and after a script that plays every exported event at every tier, on both backends. Bites: the 4 blend groups left out of the warm-up must raise the pipeline count. Smallest build: the same page with the warm-up and that script.
- **C4. No allocation per frame.** PM-0003-29's method (a sampling heap profile, 3 runs of 60 s, ADR 0003:1204) attributed to the runtime's calls with effects playing: 0 bytes; a planted 64-byte allocation per frame must show. [inferred] Today's code fails it (§2); the fix lands upstream, or in a copy. Smallest build: a page looping effects with no other system.
- **C5. Both backends.** C1 between WebGPU and `forceWebGL` on real hardware (upstream's check is headless software, README:174-175), plus PM-0003-9's cells on both.
- **C6. The export folder loaded as content.** Served under its hash and cached as immutable; a stale or altered file is refused or fetched again, in 3 cases (CD-8's pattern, ADR 0005:431-436; content item 6, plan.md:354). Upstream's `checkExport` (vfx-format/src/validate/export.ts:54) runs in the game's build, so a broken export fails the build, since the loader checks only basics (load.ts:68-123). Smallest build: that build step and one page load per case.
- **C7. Event names match the game's events.** A build-time test: every event the bridge sends for the slice's weapons (each shot, each hit per surface, each blast) names exactly one effect in `manifest.events`, and every exported event is one the game sends; it fails on a gap either way. Upstream already refuses one event answered by two effects (vfx-format/src/validate/export.ts:130-142); its names are proposals (export.md:117-118). Smallest build: a Node test over the game's event list and the manifest.
- **C8 (proposed, from the card).** Card 11 tunes "by saving the data file, which reloads within a second" (plan.md:277): a re-export reaches the running page within 1 s with C3's counters unchanged. [inferred] It needs a reload path the runtime lacks (re-run `loadExport`, then `setAtlas`).
