## Rules for every item
1. **The spike's files, read only.** The items read the netcode proof test's branch at the SHA this file was pushed
   at, df8975b or later, in one shared worktree (CHECKPOINTS.md §8: never moving the main folder):
   - `git fetch origin claude/netcode-proof-test-plan-hcky5g`, alone, and wait for it;
   - `git worktree add .gate/npt-spike df8975ba2aa779782b4029239587be3801309da9`, once (a later item that finds
     `.gate/npt-spike` already there uses it as it is).
   Below, a path like `u4-build-plan.md:685` means `.gate/npt-spike/.checkpoints/netcode-proof-test/u4-build-plan.md`
   line 685; a path starting `spikes/` or `docs/` means the same path under `.gate/npt-spike/`. Nothing in
   `.gate/npt-spike` is ever edited, and nothing is pushed to the spike branch.
2. **The item's own branch:** `git switch -c cs/<slug> origin/main` (the night's normal route), its checkpoint
   `.checkpoints/<slug>.md`, its notes folder `.checkpoints/<slug>/` (agents write there with absolute paths, saving as
   they go: CHECKPOINTS.md §4). Commit and push the checkpoint after every step. Push the branch; open **no pull
   request** (the notes are the day session's input; it folds them into PR #40 in the morning). Delete nothing.
3. **No build, no test run, no web.** The night has no cargo. A claim that only a build, a test or a run can settle is
   written down as "needs a run (day)" with the exact command for the day session, never guessed.
4. **Agents:** Opus 5.5 at `xhigh` (netcode, CLAUDE.md "Models and effort"), the agent types named per item, at most 3
   at a time. Each writes its plan into its notes file first, then a line after each finding.
5. **Findings:** each with file:line at df8975b, one severity on CLAUDE.md's scale (Critical, High, Medium, Low), the
   concrete scenario that goes wrong, and the cheapest proof the day session can run. A finding already carried to a
   later sub-unit (`u4s-carries.md`) is marked "carried (entry N)". Review budget (CLAUDE.md): U4s and U3d have had
   their two review rounds, so a Medium or Low finding becomes a follow-up for the unit's report; a Critical or High
   goes to the day session, which may open the third round the budget allows.
6. **Out of scope:** any edit outside `.checkpoints/<slug>*` on `cs/<slug>`; a pull request; a comment other than the
   night's status and report comments; the advisor (the day session takes the drafts to the advisor: the briefs after
   wave 1 merges). The night report's paragraph per item names its branch, its files and its top findings.
