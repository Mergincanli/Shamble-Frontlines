The duplicate roomFor() is not F1's business.
- **Q2: an npt-lab run's non-zero exit that is not a stop** (a) It throws sh()'s exact message, as today. **Why:** The ruling names only the stop. A non-zero npt-lab exit is the tool's own refusal: usage is 2 and Failed is 1 (lab/src/main.rs:225-246, :271-283). Today that stops the set, and INF-R2-4 does not change it.
- **Q3: the judge stopped** (a) runs.txt is written with `judge: stopped at <s> s (no verdict)`, no verdict.json is copied, and the script exits 1. Condition 1 extends the same form to any other non-zero judge exit. **Why:** The run lines are the expensive result (the P0 set's runs take about 31 minutes), and they are kept in results/runs.txt. The raw-log folder already blocks a re-run at that commit, so also making results/ costs nothing. The extension is needed because a stopped run's cut log makes the real judge exit 1 (judge/src/lib.rs:36-45). Without it, the ruled 'stopped at' line could never reach runs.txt.
- **Q4: the pre-check recording stopped** (a) The set stops before the pairs. The message is exactly `<entry name>'s recording run stopped at <s> s: the set stops before the pre-check (INF-R2-4; as carry 40's stop)`. No runs.txt is written (as with carry 40's stop), it never reads 'refused NaN rewinds', and it comes to the advisor with the runner log whole. **Why:** Each pair first checks the recording against the manifest entry (header :11-12). A cut recording therefore makes every pair refuse, a non-zero exit that throws under Q2. Going on would give nothing but refusals. Carry 40's stop (:333-334) is the existing form for 'no pair can run'.
- **Q5: 'the header says whether the lane lock is held'** (a) The module header says the set runs under the lane lock, exclusive, and gives the form, from the repository root: `flock -x .gate/shared-target/.lane.lock node spikes/netcode-proof/ops/runs/c-u4r-runs.mjs …`. Not main-run.sh, which sets CARGO_TARGET_DIR, a variable this script refuses (:255-259). The header also says each npt-lab call and the judge are bounded at 3,600 s, and the builds are not. **Why:** c-u4r-r2.mjs's header already does this (:25-26). A new required option would change the usage for no gain. The run procedure on the card is where the lock is actually held.
- **Q6: the 'Fresh' lines** (b) Add -v to both scripts' cargo build. The filter regex stays /^\s*(Compiling|Fresh) npt-/. **Why:** (a) gives less than ruled. c-u4r-runs.mjs runs outside main-run.sh (header :6-7), so nothing forces a rebuild. A build whose npt-* units are already up to date prints no Compiling line, and cargo prints Fresh only in verbose mode. That covers every set after the first at a commit, so most runner logs would hold no provenance line at all. The plan's grep cannot settle this, because main-run.sh's toucher (:47-51) makes every kept log say Compiling. -v adds stderr lines only, and those are filtered. The JSON messages stay on stdout, and builtArtifact skips non-JSON lines (check.mjs:2216). Verbosity is part of neither cargo's fingerprint nor rustc's arguments, so the binaries are the same. Confirmed at first use (condition 5).
