The gate guarantees outstanding <= N(srtt at the write) x size after each write, and outstanding never grows between writes; but srtt can FALL after the budget filled through an ACK that frees less than one snapshot: the model samples from "the first segment it newly SACKs" (tcp_model.rs:29-34), so a SACK-only ACK (a pre-burst loss holding snd_una) lowers srtt and N without lowering write_seq - snd_una. Without a pre-burst loss it cannot happen (the budget fills ~Tb + 117 ms, after the last ACK at ~Tb + 60 ms). Rare (my estimate well under 1 % per return, not measured); not seen in my 5 runs. Fix: judge each return against N at the writer's last write before it (writer_run knows it), or record that N; R13's "recorded at every return" must read it the same way.
