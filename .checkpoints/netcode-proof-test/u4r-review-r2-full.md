### SEC-U4R-R2-1 (Low)

- **Where:** .gate/u4r-snap2/spikes/netcode-proof/check.mjs:694-703 (the carry 85 (c) rule and its new comment)
- **Wrong:** The rewritten comment says that no #[path] built from a macro's fragment can bring an unread file under a listed export's allow. The widened rule only looks at text between `#[` and its `]`. A macro that puts a metavariable between `#` and `[` is never seen as an attribute, so neither the metavariable rule nor pathProblems reads it. Two forms do this: `($a:tt) => { # $a mod g; }` called as `m!([path = "x.txt"])`, and `($h:tt) => { $h [path = "x.txt"] mod g; }` called as `m!(#)`. This is the same class as SEC-U4D2-R2-3 (b) and SEC-U4R-5, and the comment again claims more than the rule does. Exploit sketch: a PR adds one of these macros to npt-hash-wasm, plus a src/x.txt with `#![allow(unsafe_code)]` and an unsafe block; the deps step passes and the crate compiles. Reach: only the two deny-level crates, npt-tcpinfo and npt-hash-wasm. Everywhere else the workspace forbids unsafe_code, and rustc refuses an allow under forbid (E0453). Neither crate defines a macro_rules today, and the code would be committed and reviewed. Hence Low.
- **Evidence:** Probe 2 in .gate/u4r-review2-security/probe.log: snap2's unsafeProblems, with crates/hash-wasm/src/lib.rs extended in memory, reports 0 new problems for `# $a` with $a:tt = [path = ..] and 0 for `$h [path = ..]` with $h:tt = #. The allow variant is caught by other rules (2 problems), and the control form #[$a] still gives 1. Probe 3: rustc 1.99.1 with --edition 2024, source on stdin and #![deny(unsafe_code)], builds both forms (exit 0). Both binaries print "module from the .txt file says 7", so the module's text came from the round-1 .txt file. rustAttributes (check.mjs:339) needs `#\s*!?\s*\[`, and pathProblems reads only those attributes (:403-411). Lint levels: Cargo.toml:101 forbids unsafe_code for the workspace; crates/hash-wasm/Cargo.toml:18 sets unsafe_code = "deny", and npt-tcpinfo is deny-level too (check.mjs:200). grep finds no macro_rules in crates/hash-wasm or crates/tcpinfo.
- **Fix:** In the two deny-level crates (EXCEPTION_LEVELS "deny"), refuse any `macro_rules` (and any `macro` item) in the mask, naming the file and line. This is SEC-U4D2-R2-3's first proposal; neither crate has one, so nothing current is refused.
