- A2 CONCLUSION (count vs timing): with held bits + press counters only, the server's release count is DEFINED as sum(steps + held_before - held_now), which telescopes to presses - held at the end (probe 3). So in COUNT terms the only release errors the echo can show are (a) a rise with no press step (doubled; now counted, heldWithoutPress) and (b) the held state at the end (lost, net). Both are asserted. A rollback whose re-rise lands with a press step is a valid history (probe 2b): a release moved in time, not doubled. What stays unseen is TIMING: a release the server applies late, until that button's next press (probe 1), or early; only loop.spec.ts:24-25's one W release (within the expect timeout of 5 s) and the end state see it. So: "0 lost and 0 doubled releases" (count) is met at the echo's resolution; "the Worker counts the presses and releases it applies through the edge counters" is NOT met for releases (no release edge counter; ADR 0002 part 5 says the post carries "press and release edge counters ... (their exact fields are ADR 0001's)", ADR 0001 part 5 has press counters only: the drafts disagree, the owner's to settle) and partly for presses (the page counts the server's echoed counters; the Worker counts nothing itself; equivalent in substance).
